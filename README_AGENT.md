# Document-grounded NSE research agent

A small Python CLI that turns a ticker and a directory of Markdown documents into a cited research brief. It uses the supplied documents as evidence, ranks official disclosures above news, separates unrelated entities, and retains an audit trail. No framework or Python packages are required.

## Run the supplied fictional test

Python 3.10+ is required. From this folder:

```sh
python3 orchestrator.py SRVCABLE 'AI innovator assignment' --provider groq --model qwen/qwen3.8-27b --review skeptical --as-of 2026-09-23 --output brief.md --audit run_audit.json
```

The script reads `GROQ_API_KEY` from the local `.env` or environment. Keep `.env` private. The source URLs are provenance, including the `.example` URLs in this pack; they are not fetched. SRVCABLE is fictional and must never be searched online. The README's assumed date, **23 September 2026**, is used for this test.

To run without credentials or network access:

```sh
python3 orchestrator.py SRVCABLE 'AI innovator assignment' --provider offline --output offline_brief.md --audit offline_audit.json
```

Offline output is deterministic, extractive, and explicitly labeled as not model-generated. A provider failure also triggers this fallback and records why. Check the audit's generation mode before describing an output as model-generated.

## Providers

The selected, unedited `brief.md` was generated by Groq's **`qwen/qwen3.8-27b`**, then passed automated checks and independent factual review. The experiments also genuinely called `openai/gpt-oss-120b`, `openai/gpt-oss-20b`, and Gemini. Gemini 2.5 Flash returned responses; Gemini 3.8 Flash/3 Flash Preview returned service errors, and 2.5 Pro returned 404 for this key. Those failures and rejected outputs remain in `evidence/`. This is a small assignment comparison, not a general model benchmark.

Provider configuration is separate from research logic. `--model` overrides `GROQ_MODEL`, `GEMINI_MODEL`, or `OPENAI_MODEL`. Automatic routing prefers configured OpenAI/gateway settings, then Gemini credentials, then Groq credentials, then offline. Use an explicit provider to make model comparisons unambiguous. Groq's default model is `openai/gpt-oss-120b`; Gemini's is `gemini-2.5-flash`.

```sh
# Gemini uses GEMINI_API_KEY (GOOGLE_API_KEY is also accepted)
python3 orchestrator.py SRVCABLE 'AI innovator assignment' --provider gemini --model gemini-2.5-flash --review skeptical --output gemini_brief.md --audit gemini_audit.json

# Another Groq text model
python3 orchestrator.py SRVCABLE 'AI innovator assignment' --provider groq --model openai/gpt-oss-20b --output groq20_brief.md --audit groq20_audit.json
```

```sh
# OpenAI or an authenticated compatible service
export OPENAI_API_KEY='your-key'
export OPENAI_MODEL='your-model'
python3 orchestrator.py REALTICKER path/to/documents --provider openai

# CLI proxy / compatible gateway (base includes /v1 if required by that service)
export OPENAI_BASE_URL='http://127.0.0.1:8080/v1'
export OPENAI_MODEL='your-proxy-model'
python3 orchestrator.py REALTICKER path/to/documents --provider openai
```

Do not put secrets into source documents or commit them. API-backed runs send accepted document evidence to the configured inference endpoint. Inference calls are distinct from browsing for research.

Provider references: [Groq API reference](https://console.groq.com/docs/api-reference), [OpenAI Chat Completions reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create), [Gemini compatibility reference](https://ai.google.dev/gemini-api/docs/openai). No live OpenAI credentials are required for the supplied Groq, Gemini, or offline runs. `OPENAI_BASE_URL`, `GEMINI_BASE_URL`, or `--base-url` may point at a compatible endpoint; the base must not include `/chat/completions`.

## Document contract and behavior

Each source is a UTF-8 Markdown file beginning with metadata:

```markdown
---
source: Company investor relations
url: https://example.com/results
published: 2026-09-01
type: official company filing
---

# Company Ltd (NSE: REALTICKER)
Document evidence follows.
```

The original pack and its archive remain untouched. Instruction files and READMEs without valid source metadata are not research evidence. Dates, URLs, source type, and identity are validated before synthesis. Missing, ambiguous, unrelated, future-dated, and promotional material is tracked in the audit rather than silently folded into the company's evidence.

The writer prompt is in `system_prompt.md`. It requires citations after factual claims, explicit conflicts, resistance to embedded instructions, company disambiguation, no hidden chain-of-thought, and no buy/sell recommendation. Review strategies change the model's scrutiny: balanced, conservative, skeptical. The final Sources section is rendered from source metadata.

The pipeline is: validate sources → establish official ticker identity → quarantine unrelated/promotional/injected material → extract paragraph/table evidence and period-aware conflicts → ask the configured model for structured claims referencing evidence IDs → validate citations, selected evidence, numbers, key scope checks and coverage → render Markdown. API/JSON/validation failures fall back to deterministic extraction. Each run gets a unique artifact directory beside its audit, so earlier responses survive later runs.

IDs are filename-sorted and stable for an identical valid corpus; adding/removing a source can renumber them. The audit's filename/hash mapping identifies the exact corpus. Input is non-recursive: place source Markdown files directly in the supplied directory. Front matter uses the four plain scalar fields shown above; quoted YAML, nested YAML and extra fields are intentionally outside this small parser's contract. Limits are 100 KB per document and 500 KB per corpus; invalid files are reported rather than partially interpreted.

## Optional live sources

Live mode is a small explicit-URL Markdown tool, with no automatic search or PDF/HTML scraping. Use it only with a real ticker and known research URLs:

```sh
python3 orchestrator.py REALTICKER path/to/local-docs --live-data --live-url 'https://your-research-host.example/results.md' --provider offline --output live_brief.md --audit live_audit.json
```

The example URL is a placeholder: substitute an actual trusted HTTPS Markdown endpoint with the same source metadata contract. Both opt-in and explicit URLs are required; the fictional SRVCABLE path is rejected before any retrieval. Public HTTPS URLs only, up to five documents, no redirects. Retrieved URL/time and document provenance are recorded separately. Metadata URLs are never automatically fetched. This path was tested with mocks; no live real-ticker research run was requested or performed.

## Practical limits

Citation, numeric, period and wording checks are conservative heuristics, not proof of semantic entailment. Independent review caught errors that early automated checks missed; inspect an output before relying on it. Conflict extraction handles explicit financial table rows and several common prose metrics with identifiable quarters; unfamiliar metrics, ambiguous periods, units, scopes or multiple-period narrative may need human review. Company resolution requires a unique official company-name/NSE-ticker anchor and otherwise fails conservatively. Source types/URLs are supplied metadata, not authenticated filings. Prompt injection screening is heuristic in addition to the writer's untrusted-data policy.

The optional URL fetcher is intended for trusted public research endpoints, not hostile multi-user deployment; DNS is checked before urllib connects and is not pinned against rebinding. Offline synthesis is less polished, retains some source phrasing, and does not infer missing facts. The final brief retains common abbreviations such as ITC, CGST and bps to preserve its exact generated text.

## Reproduction and review

`TEST_LOG.md` contains commands, actual outcomes, failures, revisions, independent review, and validation evidence. Run artifacts retain prompts, visible model responses, source records, validation outcomes, and provider usage without API keys or private model reasoning. `brief.md` is generated by the program; it is not manually rewritten.

Run the automated checks:

```sh
python3 -m unittest discover -s tests -v
```

The assignment also asks for a personal 2–3 minute screen recording showing a run, a design decision, and a limitation. This repository's logs are execution evidence; a narrated screen recording remains a submission step.
